# Дорожная карта: полный охват лучевой диагностики

**Миссия:** открытое программное обеспечение, которое позволяет среднему медицинскому работнику **интерпретировать любое лучевое исследование на уровне профильного специалиста без эскалации** — дешевле, чем штатный рентгенолог, и с равной надёжностью.

Обучение моделей **распределено между волонтёрами сообщества**: каждый участник обучает задачи на своём железе (домашняя GPU, Kaggle/Colab, арендованные инстансы). Дорожная карта определяет только *что* и *как*; она не завязана на мощность какой-либо одной машины.

> [English](ROADMAP.en.md) · [Русский](ROADMAP.ru.md) · [中文](ROADMAP.zh.md)

---

## 1. Ви́дение и экономика

- **Почему дешевле:** одна закупка ПО и развёртывание против постоянного ФОТ специалиста; работа 24/7; единый стандарт качества в любой точке (ФАП, амбулатория, поле).
- **Модель замещения:** «средний специалист + ИИ = результат профильного рентгенолога». ИИ не консультирует «вверх», а даёт специалисту знания и проверяемую интерпретацию на месте.
- **Что продаём:** авто-протокол по каждому исследованию (ОПИСАНИЕ → ЗАКЛЮЧЕНИЕ → РЕКОМЕНДАЦИИ), экономический калькулятор «себестоимость исследования», Docker-сервис.
- **Открытость:** код GPL-3.0-or-later; каждое обучение и веса — открытые, чтобы любой мог воспроизвести и улучшить.

## 2. Метод: сквозной конвейер для каждой задачи

Каждая модальность проходит полный цикл:

```
классификация → локализация (bbox/seg) → количественные измерения → авто-протокол → эвалюация
     (AUROC/AP)        (IoU/dice)               (R²/δ)                  (UAT)         AUROC/AP/dice/R²
```

Принципы:
- **DICOM-first**, но с bridge-конвертацией в PNG/JPEG (соблюдая соблюдение Windowing).
- **Реестр задач** — каждая модальность описывается единой структурой (см. §4).
- **Эвалюация на фиксированных val-сплитах** с воспроизводимым seed — без «подгонки».
- **Калибровка порогов** по метрике Youden, мультиязычный вывод (en/ru/zh).

## 3. Участие сообщества (как это работает)

Обучение — волонтёрское. Для каждой задачи в реестре указываются:

- **pickup-пакет** — ссылки на датасет, конфиг, скрипт запуска, ожидаемый бюджет GPU (например «4 часа на T4»);
- **target-градации** — «baseline / good / best» с ожидаемыми метриками;
- **сдача результата** — веса в HF Hub или Google Drive, чек-лист отчёта (метрики, реплики воспроизведения, скриншоты);
- **рецензирование** — владелец задачи проверяет отчёт и течение в реестр.

Это позволяет: новичку начать с маленькой задачи на одной GTX (разрешение 256–512, батч 4–8), а опытному — взять КТ-задачу с дистилляцией 3D→2.5D на 2×GPU.

### Фаза 1 — CXR полный набор (15 доступных классов) ✅ done
- **Задача:** дообучить не-лёгочные классы, присутствующие в данных: Cardiomegaly, Aortic enlargement, Calcification, ILD (в дополнение к 11 лёгочным).
- **Данные:** Kaggle-зеркало VinDr-CXR (`train.csv`, 15 000 снимков) — доступны **15 колонок** меток. Полный набор из 28 классов (фрактуры рёбер/ключицы, эмфизема, смещение средостения и др.) требует исходный VinDr-CXR с PhysioNet (регистрация/лицензия) — тогда эти классы появятся и будут дообучены тем же `train.py`.
- **Метод:** `uv run vindr-train --config configs/train_full.yaml` (labels=all, 15 классов); class-weights для редких.
- **Результат:** `runs/full_v1_b0_512/best.pt` (эпоха 7). macro-AUROC **0.950**, все 15 классов ≥ 0.85; слабейшие (редкие): Pneumothorax 0.850 (96 сэмплов), Other lesion 0.913.
- **done:** AUROC ≥ 0.85 на 15 классах; макросредний ≥ 0.90. — ✅ достигнуто
- **Бюджет:** ~4–6ч на GTX 1650 / ~2ч на T4 — подтверждён (~3.5ч, 12 эпох).

### Фаза 2 — CXR-детекция и измерения 🔧 в работе (код готов)
- **Данные уже скачаны:** `vindr-cxr-coco` (VinDr-Ad, bbox) — готовые якоря для детекции.
- **Задача A:** детектор находок (YOLOv8s) — box/mAP50 ≥ 0.5; imgsz=1024 (объекты мелкие: медиана ~0.2% кадра).
- **Код готов:** конвертер COCO→YOLO (`scripts/coco2yolo.py`), детекция в CLI (`predict --detect`) и веб (`/predict/det`), Colab-ноутбук для облачного обучения.
- **Задача B:** количественные признаки (кардиоторакальный индекс, уровень жидкости, «треугольная тень»).
- **Обучение и проверка — в самом конце** (см. §6): код пишется первым, веса обучаются и валидируются единым финальным прогоном.
- **done:** mAP50 ≥ 0.5; R² ≥ 0.9 для измерений на размеченном подмножестве.

### Фаза 3 — КТ головы (раздел «Мозг») 🟡 код готов
- **Задачи:** инсульт (ишемический/геморрагический), гематомы (эпи-/субдуральная/САК), опухоли (менингиома, глиома, метастазы), травма (переломы свода), признаки смещения.
- **Данные:** RSNA ICH, CQ500, Head-CT datasets (HF), BraTS (МРТ, для опухолей).
- **Метод:** 2.5D (≥3 среза, полу-3D) на GTX 1650 уже возможен; дистилляция 3D→2.5D для сильных сетей.
- **Нюанс конспекта:** дифференцировать гематому по локализации (двояковыпуклая в пределах швов = эпидуральная; ничем не отграничена = субдуральная; по бороздам = САК) — закодировать в семиотику отчёта.
- **Код готов:** загрузка DICOM / 16-bit PNG / NIfTI в HU (`src/vindr/ct/volume.py`), скрипт подготовки RSNA (`scripts/prepare_head_ct.py`), slice-модель и study-модель с attention-пулингом для 5 подтипов RSNA + `any` (`src/vindr/ct/model.py`), 2.5D датасеты (`dataset.py`), цикл обучения (`train.py`, `vindr-ct-train`), инференс с JSON-отчётом (`predict.py`, `vindr-ct-predict`), HU-измерения — плотность/объём очага, смещение средней линии, индекс Эванса (`measure.py`).
- **Слабо-размеченные данные (в RSNA есть посрезочные метки, но нет пиксельных масок):** `src/vindr/ct/pseudo.py` добывает псевдо-маски из обученного посрезочного классификатора — CAM на срез → hi-res карта признаков → GrabCut с seed из ядра CAM → полоса HU острой крови (50–110, настраивается; хронические коллекции около 25 HU требуют другой полосы) → 3D-маска исследования, плюс `pseudo_labels.json` с доказательствами (max/mean вероятность, диапазон z, число размеченных срезов), чтобы обучение могло фильтровать по качеству. Три предохранителя честности меток: CAM должен быть *концентрированным* (`cam_sharpness` — у нормализованного CAM максимум равен 1.0 по построению и ничего не говорит), seed GrabCut задаётся числом пикселей, а не порогом значения (порог на плоском CAM вырождается во «весь срез»), а полоса HU читается по **нативным** вокселям — ресемплинг усредняет кровь 70 HU с мозгом 30 HU и воздухом, и полоса, посчитанная на сетке сети, удаляет ровно то кровоизлияние, которое должна подтвердить. Каждый нативный срез проверяется через карту native→grid, так что грубая сетка не может пропустить тонкое кровотечение. `python -m vindr.ct.pseudo_mine --ckpt … --data-dir … --out-dir …` делает symlink изображений рядом с каждым `mask.npy`, и этот набор читает `vindr-ct-seg-train` напрямую. Это псевдо-метки, не ground truth: полоса HU и семиотика очагов — непроверенные эвристики, а Dice ≥ 0.7 из ROADMAP не подтверждён без реального пиксельного набора.
- **Код локализации готов:** 2.5D U-Net для маски кровоизлияния (`src/vindr/ct/segmentation.py`, BCE + soft Dice, `dice_score`/`iou_score`), загрузчик масок рядом со снимком — `mask.nii.gz` / `mask.npy` / `masks/*.png` / `*_mask.png` (`dataset.py`, `HeadCTSegDataset`), цикл обучения сегментации (`train_seg.py`, `vindr-ct-seg-train`, `configs/train_head_ct_seg.yaml`), извлечение 3D-очагов и семиотика по конспекту (`src/vindr/ct/lesions.py`): компоненты объединяются по соседним срезам, двояковыпуклая у кости → эпидуральная, серповидная через среднюю линию → субдуральная, извитая → САК, округлая в паренхиме → внутримозговая, плюс объёмы и bounding box. Подключено к инференсу через `predict --seg-ckpt` (опционально `--save-mask`); `vindr-ct-predict --ckpt … --seg-ckpt …` отдаёт подтипы и локализацию вместе. Пайплайн покрыт 94 тестами, включая сквозной прогон синтетический классификатор → pseudo-mine → `load_masked_studies` → `train_seg`.
- **Ещё не закодировано:** модели опухолей, модели переломов (эвристика по HU есть в `measure.py`).
- **Открытый вопрос по данным:** локализация требует попиксельных масок. В релизе RSNA 16-bit PNG только посрезочные метки, поэтому перед финальным прогоном нужно выбрать набор с масками (например, PhysioNet segmentation). Семиотика выше — эвристические морфологические признаки, а не диагноз.
- **Обучение и валидация — в самом конце** (см. §6): сначала весь код, затем один финальный прогон обучения и валидации.
- **done:** бинарные AUROC ≥ 0.90 (кровоизлияние), ≥ 0.85 по подтипам; локализация dice ≥ 0.7.

### Фаза 4 — КТ почки/надпочечники + средостение ⬜ open
- **Задача A (по конспекту):** аденома надпочечника — плотность < 10 HU (порог); вымывание ≥ 50–60% к 10 мин; похожесть кисты (не накапливает контраст). Это «измерения по HU».
- **Задача B:** хронический пиелонефрит (истончение паренхимы, снижение контрастирования), нефросклероз («сморщенная почка»), поражение чашечек.
- **Задача C:** средостение — тимома (стадии инвазии), тератома (неоднородная), внутригрудной зоб, кисты (тонкостенные округлые), лимфома (лимфоузлы < 1 см — норма).
- **Данные:** проверить KiTS/Kidney-Tumor-Seg (почки), собрать/найти средостенные (частные/поиск).
- **done:** Аденома AUC-per-lesion ≥ 0.85; сегментация почек dice ≥ 0.85.

### Фаза 5 — КТ пазух носа ⬜ open
- **Задачи:** синусит (утолщение слизистой, уровень жидкости), полипозный синусит, мукоцеле (расширение пазухи с ремоделированием кости), грибковое тело (мицетома, гиперостоз/разрушение стенки), злокачественные (без чётких границ).
- **Данные:** поиск/сбор открытых CT-синусов (англ. "sinus CT dataset"), либо анонимизированный добор.
- **done:** clf бинарный синусит AUROC ≥ 0.90; мукоцеле/топология сегментация dice ≥ 0.7.

### Фаза 6 — Рентген скелета / переломы ⬜ open
- **Задачи:** переломы ключицы, рёбер, длинных костей/запястья; детекция box.
- **Данные:** MURA (9912, плечевой/локтевой/запястье), GRAZPEDWRI (детские, 10.2k).
- **Метод:** тот же detection-пайплайн, что Фаза 2; граничный контраст хороший.
- **done:** MURA AUROC ≥ 0.88; box-mAP50 ≥ 0.5.

### Фаза 7 — ЖКТ (барий / ирригоскопия) 🔬 самое амбициозное
- **Задачи:** ахалазия пищевода (1–3 стадии по задержке бария), варикоз вен пищевода (деформация контура), дивертикулы (Ценкера, бифуркационные, эпифренальные), чаши Клойбера (острая непроходимость), синдромы рельефа слизистой.
- **Метод:** временные серии → видео/VLM-подход (последовательность кадров при рентгеноскопии). Это самая тяжёлая по данным/вычислениям задача.
- **done:** бинарная классификация ахалазии AUROC ≥ 0.85; непроходимость — det узлов уровня.

### Фаза 8 — Интеграция и экономика ⬜ open
- Авто-протоколы для всех модальностей (единый XML/JSON-формат отчёта → печать).
- Docker-сервис: приём DICOM, батч-инференс, веб.
- **Калькулятор замещения:** себестоимость исследования (электроэнергия, амортизация, лицензии) против стоимости оплаты труда рентгенолога; вывод «безубыточности» по объёму исследований.
- **Пакет «триаж по модальностям»:** CXR + КТ головы + пазухи в одном развёртывании.

## 6. Обучение и валидация моделей — в самом конце 🔚 единый финальный прогон

**Принцип:** сначала пишется **весь код всех фаз** (все системы органов — от CXR до ЖКТ), и только когда программа полностью готова, **одним финальным этапом** обучаются и проверяются все веса. Так архитектуру, конфиги и пайплайны можно менять до дорогого обучения, а модели учатся на финальной версии кода.

**Порядок финального прогона (когда готов весь код):**
1. **Классификатор CXR (Фаза 1) — уже обучен** ✅ macro-AUROC **0.950** (`runs/full_v1_b0_512/best.pt`).
2. **Детектор CXR (Фаза 2)** — облачный T4 (Colab), `notebooks/phase2_det_colab.ipynb`, imgsz=1024, batch 16, до 40 эпох, patience 15. Цель mAP50 ≥ 0.5.
3. **Все модели КТ/МРТ (Фазы 3–8)** — обучаются одним пакетом после готовности их кода: КТ головы, почки/средостение, пазухи, скелет, ЖКТ. Тяжёлые (2.5D/3D) — на T4/A100 волонтёров.
4. **Валидация всех моделей** — прогон метрик из §7 по каждой модели; проверка измерений (КТИ R²) на размеченном подмножестве.
5. **UAT протоколов** — оценка врачом/фельдшером (≥ 95% корректности структуры).

Веса не коммитятся в репозиторий (в `.gitignore`), хранятся отдельно и привязываются к коммиту через release/README.

## 9. Как начать (quick start для волонтёра)

1. Клонировать репозиторий, `uv sync` (окружение упаковано).
2. Взять задачу статуса `open` из реестра (§4) — например `cxr_full_28` или `cxr_det_vindr`.
3. Написать код задачи (пайплайн, конфиг, метрики) — **обучение не запускать**, см. §6.
4. Прогнать `vindr-eda` и `vindr-predict` на случайных примерах, сдать код + отчёт.

Каждая фаза фиксируется PR-ом к этому файлу (чекбокс done → отмечен, веса в релизах).
